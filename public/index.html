        How this works

        • What is checked. Once a day, each site's /robots.txt is fetched and read the way the robots.txt standard (RFC 9309) describes. This measures what sites ask AI bots to do, not what the bots actually do: some bots that act on a user's request say robots.txt may not apply to them.
        • Blocked, partly blocked, allowed. Blocked: the bot may not access the site's root (/) and nothing is allowed back. Partly blocked: the root is blocked but some paths are allowed back, or the bot's own rules block specific sections. Generic rules for all bots (like /admin/) don't count.
        • Purposes. Training bots collect content to train AI models. Search bots index pages so AI search tools can cite them. User bots fetch a page live because someone asked an AI assistant. Each bot's purpose comes from its operator's documentation. A site counts as blocking a purpose if it blocks at least one current bot of that kind. Old bot names are reported separately.
        • Unknown sites are left out of percentages. If a site returned an error, couldn't be reached, or answered with something other than a robots.txt (often a bot check), we can't know its policy, so it's counted separately instead of as "allowed". A site with no robots.txt at all (404) counts as allowing every bot, as the standard says.
        • Cloudflare. A site counts as using Cloudflare if its response carries Cloudflare's cf-ray header. "Managed robots.txt" means the file contains the section Cloudflare adds automatically for its customers.
        • Sample. Around 70 Portuguese sites: national news media, broadcasters, sports media and clubs, tech and lifestyle sites, universities and public institutions. Percentages from small groups can move a lot when one site changes.
